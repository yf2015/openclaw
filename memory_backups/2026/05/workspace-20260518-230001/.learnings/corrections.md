## 一、长期有效教训

1. **日志维护不能断** — 4/22~5/8 断档16天，根因：cron心跳写日志机制丢失。以后每次心跳必须写日志，无日志=任务失败。
2. **强推风险** — `git push --force` 会抹掉历史，任何 force push 前必须确认分支状态。
3. **心跳≠复盘** — 心跳用于快速轻量检查，复盘用于系统性回顾，是两个独立机制。钉钉环境下email/calendar检查不适用，以集思录推送状态为主。
4. **建议需同步落地** — 任何新建建议需同步实施或转cron，不可只写不执行。5天无行动则关闭或升级。

## 二、复盘流程改进

1. **复盘必须产生跟进** — 待确认项48小时内无行动则升级为「未完成待处理」，不再无限期挂起。
2. **复盘缺失环节** — 复盘流程本身缺少「落实检查」，待确认项应在下次复盘前实际检查，而非重复列出。
3. **建议需跟进** — 任何新建建议需同步落地，执行和计划之间不能断。
