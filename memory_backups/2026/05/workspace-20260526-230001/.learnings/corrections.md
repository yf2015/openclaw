## 一、长期有效教训

1. **日志维护不能断** — 4/22~5/8 断档16天，根因：cron心跳写日志机制丢失。以后每次心跳必须写日志，无日志=任务失败。
2. **强推风险** — `git push --force` 会抹掉历史，任何 force push 前必须确认分支状态。
3. **建议需同步落地** — 任何新建建议需同步实施或转cron，不可只写不执行。5天无行动则关闭或升级。
4. **待确认项不过夜** — 超过48小时无行动则关闭或升级，不在复盘中重复列出同一个待确认项。

- **复盘缺失环节**：待确认项应在下次复盘前实际检查，而非重复列出
- **钉钉环境特殊**：email/calendar 检查不适用，以集思录CB推送状态作为系统正常指标
